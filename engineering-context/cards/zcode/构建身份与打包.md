# zcode / 构建身份与打包

## 职责

决定打出的 mac 安装包叫什么（ZCode vs ZCode Preview）、连哪个后端、落在哪个数据目录；以及从源码到 .app/.dmg 的完整构建链。

## 权威实现与对外接口

- 身份两轴（`packages/desktop/scripts/desktop-product-identity.mjs:59-68`）：后端环境 `ZCODE_ENV`（production|test，缺省 test）× 身份 `ZCODE_PREVIEW_IDENTITY`（仅 `1`/`0` 合法，其它拼写构建期抛错 :40-51）。production 后端 + Preview 身份 = `dev.zcode.app.preview` / `ZCode Preview`（:17-24），与正式版并排安装。
- 打包入口：根 `package.json` `bundle:desktop` → `packages/desktop/scripts/bundle.mjs`：`pnpm prepare:runtime-assets` → `pnpm build` → `electron-builder --config electron-builder.config.js --mac --arm64` → asar 依赖闭包/越界 native 机械校验 → 体积审计（bundle.mjs:700-745）。默认 mac/arm64。
- 产物：`packages/desktop/dist/mac-arm64/ZCode[ Preview].app`（unpacked，可直接安装）+ dist 下 `.dmg`/`.zip`。
- `ZCODE_AUTO_UPDATE` 构建期注入（`scripts/build-time-config.mjs:44-47` → vite/tsup define，`packages/desktop/vite.config.ts:15-19`）；开源仓库无私有默认值文件，不设即关闭。
- mac 签名：`ZCODE_ENABLE_MAC_SIGN=1` 且有 APPLE_SIGNING_IDENTITY 才签（`packages/desktop/electron-builder.config.js:59-62`），`identity: null`（:833）、`notarize: false`（:837）。
- Electron 下载默认 npmmirror 镜像（bundle.mjs:125）。
- Node/pnpm 版本钉死：`mise.toml:3-4`（Node 24.14.0 / pnpm 10.33.2）；`pnpm install` 后直接 bundle 即可（bootstrap 面向 dev，非构建必需）。

## 陷阱项

- `ZCODE_ENV` 不设 = test 后端 =  Preview 身份 + 测试内置 provider——想连生产必须显式 `ZCODE_ENV=production`（`scripts/builtin-provider-config.mjs:14-45`）。
- CUA helper 只在私有 producer 安装时随包（`electron-builder.config.js:68-70` isRealComputerUseProducerInstalled）——开源构建可能缺 computer-use 运行时。
- bundle 的产物校验很严（依赖闭包、native 越界），改打包配置后过不了校验会直接失败，这是故意的。
