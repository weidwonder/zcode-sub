# zcode / 数据目录与迁移

## 职责

用户数据在磁盘上的布局（`~/.zcode`）、三个 SQLite 库的迁移账本机制、以及跨版本打开（升级/降级）时的兼容行为。

## 权威实现与对外接口

- 布局（`packages/services/src/paths.ts:45-58`）：`~/.zcode`（getZCodeDataRootDir）→ `v2/`（getAppConfigDir：credentials.json、setting.json、bot-config.v3.json、tasks-index.sqlite）+ `cli/db/db.sqlite`（会话库，桌面与 CLI 共享）+ skills/agents/plugins 等。**与 flavor/appId 无关**——Preview 与 production 共享全部业务数据（官方注释：`packages/desktop/src/main/desktopRuntimeEnv.ts:576-578`）。
- Electron userData 才随身份分：`~/Library/Application Support/ZCode[ Preview]`（desktopRuntimeEnv.ts:65-82）。
- 迁移账本三套，同一执行器 `packages/shared/src/sqlite-migrations/runner.ts:62-100`：
  | 库 | 账本表 | 清单 |
  |---|---|---|
  | cli/db/db.sqlite | `schema_migration`（含 app_version、time_applied） | `apps/zcode-cli/packages/adapters/src/storage/session-store/migrations.ts` |
  | v2/tasks-index.sqlite | `tasks_schema_migration` | `packages/services/src/session/tasksDatabase/migrations.ts:66-122`（base scope） |
  | 同上库内项目存储 | `schema_migration`（app_version=产品版本） | `packages/services/src/project-storage/index.ts:29-57` |
- checksum：会话库/项目存储 = sha256(sql.trim())（runner.ts:114-116）；任务索引 = sha256(JSON.stringify(checksumInput))（tasksDatabase/migrations.ts:146-148）。
- 迁移前自动备份到 `~/.zcode/backup`（backupDirectories，migration-runner.ts 调用参数）。
- message/part 的 data 列解码宽松（JSON.parse + spread，`apps/zcode-cli/packages/adapters/src/storage/session-store/codecs.ts:86-119`，注释明确考虑回滚缺字段）；setting.json 校验失败回退默认不阻断启动（`packages/services/src/setting/settingService.ts:139-147`）。

## 陷阱项

- **降级安全的关键机制**：runner 只校验清单内条目的 checksum，对账本里多出的（新版应用的）迁移 id 无任何检查——降级不会因未知迁移报错；真正会炸的是上游修改**已应用**迁移的 SQL（MigrationChecksumError，runner.ts:70-71）。
- 实测 2026-10-27：用户库三账本（0024 / 0006 / 0007）与 3.16.2 源码清单完全同代、checksum 全匹配——3.16.2 打开 3.16.3 数据安全（证据与方法：`docs/report/zcode-patched-build-compat.md` §1）。
- 降级期间的渐进损耗：旧版保存设置会抹掉新版新增设置键；消息行被旧版写回会丢新增字段。
- 会话库可达 1 GB 且 WAL 活跃——备份必须用 sqlite3 在线备份（`.backup`），文件复制会撕裂。

## 确认

2026-10-27，通读 runner.ts / 三处迁移清单 + sqlite3 -readonly 查询用户库账本 + 逐条 checksum 复算比对。
