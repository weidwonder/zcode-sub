# zcode / 更新与强制升级

## 职责

打包版的两道版本门：自动更新器与启动期强制升级检查。决定「旧版本客户端能不能继续连生产后端」。

## 权威实现与对外接口

- 自动更新：`packages/desktop/src/main/index.ts:2209`，`enabled: ZCODE_PRODUCT_FLAVOR === "production" && ZCODE_AUTO_UPDATE_ENABLED`（后者是构建期 define）。Preview 一律不启用。
- 强更门：`index.ts:2521-2532`，`production && app.isPackaged` 时启动调 `maybeBlockStartupForForceUpdate`（`packages/desktop/src/main/forceUpdateGuard.ts:217-254`）：
  - 拉 `<endpoint>/api/v1/client/configs?app_version=<v>&platform=<p>`（10s 超时；**失败/断网 → 跳过校验放行**，forceUpdateGuard.ts:175-179）。
  - `data.configs.forceUpdate.minimalVersion`（键解析 `packages/shared/src/remoteAppConfig.ts:80-94`）> 当前版本（semver 严格比较，`packages/shared/src/forceUpdate.ts:119-137`，支持 "45"/"4.5" 简写补全）→ 弹窗 → 用户只能升级或退出，不进主界面。
  - Preview：官方代码显式跳过（index.ts:2533-2534）。
- 本地未打包 dev（isPackaged=false）也跳过（index.ts:2515-2521 注释：防 feature 分支版本滞后被误杀）。

## 陷阱项

- **`ZCODE_AUTO_UPDATE=0` 关不掉强更门**——两道门独立，强更门只看 flavor + isPackaged。
- 实测 2026-10-27：生产 configs 未下发 forceUpdate 键，3.16.2 可正常启动；但服务端随时可下发。
- 服务端按 `app_version` 参数下发配置与灰度——把补丁版版本号伪标成 3.16.3 会持续领取 3.16.3 的服务端行为配 3.16.2 的代码，错配面不可枚举；不可取。
