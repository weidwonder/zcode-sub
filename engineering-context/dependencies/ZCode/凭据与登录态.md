# 业务域卡 — ZCode › 凭据与登录态

## 职责

登录凭据的存储位置、加密方式与生命周期；回答「替换/并存 app 后要不要重新登录」。

## 权威实现与对外接口

| 能力 / 入口 | 权威实现（cite，路径相对 ZCode 仓库根） | 约束 / 要点 |
|---|---|---|
| 凭据文件 | `packages/services/src/credential/credentialService.ts`（31-33 行，目录取 `#getAppConfigDir`） | `~/.zcode/v2/credentials.json`，与 flavor/app 替换无关 |
| OAuth token 键 | `packages/services/src/oauth/oauthService.ts`（1037 行） | 键形如 `oauth:zai:access_token`，全走 credentialService |
| 凭据加密 | `packages/services/src/credential/providers/credentialCipherProvider.ts#defaultCredentialSecret`（20-38 行） | AES-256-GCM；密钥 = `sha256(env.ZCODE_CREDENTIAL_SECRET ‖ "zcode-credential-fallback:{platform}:{homedir}:{username}")`——纯本机派生，**不用钥匙串、与代码签名无关**；同机同用户恒定 |
| TCC 权限（CUA 用） | `packages/desktop/src/main/cuaAccessibilitySettings.ts`（70 行 PERMISSION_STAGE_ORDER） | 辅助功能/录屏授权绑定应用签名身份；官方签名 → ad-hoc 替换后失效，需重新授权；不用 CUA 无感 |

## 陷阱项

- Electron `safeStorage` / 钥匙串 — 全仓未使用（仅 `credentialService.ts` 23 行一条「后续可切换」注释）；不存在换签名导致钥匙串弹窗的问题。
- `ZCODE_CREDENTIAL_SECRET` 若被设置过 — 凭据即与该环境变量绑定；排查「密钥不匹配或密文已损坏」先查它（credentialCipherProvider.ts 25-27 行）。
