# 业务域卡 — ZCode › 构建身份与打包

## 职责

决定打出的 mac 安装包叫什么（ZCode vs ZCode Preview）、连哪个后端、落哪个数据目录；以及从源码到 .app/.dmg 的完整构建链。

## 权威实现与对外接口

| 能力 / 入口 | 权威实现（cite，路径相对 ZCode 仓库根） | 约束 / 要点 |
|---|---|---|
| 身份解析（production/preview 两轴） | `packages/desktop/scripts/desktop-product-identity.mjs#resolveDesktopProductFlavor`（59-68 行） | 后端环境 `ZCODE_ENV`（production\|test，缺省按 test）× 身份 `ZCODE_PREVIEW_IDENTITY`（仅 `1`/`0` 合法，其它拼写构建期抛错，见同文件 `isPreviewIdentityRequested` 40-51 行）；production 后端 + Preview 身份 = `dev.zcode.app.preview` / `ZCode Preview`，与正式版并排安装 |
| 打包入口 `pnpm bundle:desktop` | `packages/desktop/scripts/bundle.mjs#main`（700-745 行） | 内部串行：`pnpm prepare:runtime-assets` → `pnpm build` → `electron-builder --mac --arm64` → asar 依赖闭包/越界 native 机械校验 → 体积审计；默认 mac/arm64 |
| unpacked .app 产物 | `packages/desktop/scripts/bundle.mjs#resolveAppAsarPath`（607-620 行的路径规则） | `packages/desktop/dist/mac-arm64/ZCode[ Preview].app` 可直接安装，无需挂 dmg；dist 下另有 `.dmg`/`.zip` |
| 构建期开关注入 | `scripts/build-time-config.mjs#resolveBuildTimeConfig`（44-47 行） | `ZCODE_AUTO_UPDATE` 经 vite/tsup define 注入（`packages/desktop/vite.config.ts` 15-19 行）；开源仓库无私有默认值文件，不设即关闭 |
| macOS 签名开关 | `packages/desktop/electron-builder.config.js`（59-62 行 shouldEnableMacSigning、833 行 `identity: null`、837 行 `notarize: false`） | `ZCODE_ENABLE_MAC_SIGN=1` 且有 APPLE_SIGNING_IDENTITY 才签；开源本地构建即未签名包 |
| Electron 下载镜像 | `packages/desktop/scripts/bundle.mjs#DEFAULT_ELECTRON_MIRROR`（125 行） | 默认 npmmirror，国内网络友好 |
| 版本钉死 | `mise.toml`（3-4 行） | Node 24.14.0 / pnpm 10.33.2；`pnpm install` 后直接 bundle 即可（bootstrap 面向 dev，非构建必需，README「准备」节） |

## 陷阱项

- `ZCODE_ENV` 缺省 — 按 test 处理＝测试后端＋Preview 身份＋测试内置 provider（`scripts/builtin-provider-config.mjs` 14-45 行），连生产后端必须显式 `ZCODE_ENV=production`。
- CUA helper 只在私有 producer 安装时随包 — `packages/desktop/electron-builder.config.js` 68-70 行 `isRealComputerUseProducerInstalled`；开源构建可能缺 computer-use 运行时。
